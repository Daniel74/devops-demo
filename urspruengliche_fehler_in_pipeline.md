| Symptom / Risiko                                                                                                                                                      | Ursache                                                                                                                                            | Fix                                                                                                                                                                                         |
| :-------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1. Unnötige Pipeline-Läufe:** Der Workflow startet bei jedem Push und jedem Pull Request auf beliebigen Branches, nicht nur bei Änderungen an `main`.               | Die Trigger `on.push` und `on.pull_request` hatten keinen `branches`-Filter.                                                                       | `branches: [main]` sowohl bei `push` als auch bei `pull_request` ergänzen.                                                                                                                  |
| **2. Python-Version Fehler:** Run bricht ab (`setup-python` meldet unvollständige Version `3.1`)                                                                      | Die Versionsnummer `3.10` steht ohne Anführungszeichen                                                                                             | Anführungszeichen setzen: `python-version: "3.10"`                                                                                                                                          |
| **3. Test-Fehler:** `pytest: command not found` beim Ausführen der Tests.                                                                                             | Der Test-Step (`pytest`) ist vor dem Installations-Step der Dependencies platziert.                                                                | Reihenfolge tauschen: Zuerst `python -m pip install -r requirements.txt`, dann `python -m pytest -v` ausführen                                                                              |
| **4. Installations-Fehler:** `Could not open requirements file: [Errno 2] No such file or directory: 'requirement.txt'`.                                              | Tippfehler im Dateinamen der Requirements (`requirement.txt` statt `requirements.txt`).                                                            | Dateinamen korrigieren auf `requirements.txt`.                                                                                                                                              |
| **5. Caching-Problem:** Der Pip-Cache wird nie aktualisiert; bei neuen Dependencies werden veraltete Pakete geladen.                                                  | Der Cache-Key ist statisch (`key: pip-cache`) ohne Hash-Prüfung.                                                                                   | Dynamischen Key mit `hashFiles('requirements.txt')` und `restore-keys` verwenden.                                                                                                           |
| **6. Caching wirkungslos:** Der Pip-Cache hatte keinerlei Effekt, da im Job, in dem er lag, keine Dependencies installiert werden.                                    | Der `Pip-Cache`-Step war im falschen Job (`release`) platziert statt im `test`-Job, in dem `python -m pip install` tatsächlich ausgeführt wird.    | `Pip-Cache`-Step in den `test`-Job verschieben, direkt vor den Schritt „Dependencies installieren“.                                                                                          |
| **7. Build-Fehler & Unvollständige Pipeline:** Build schlägt fehl (`No such file or directory: 'src/'`) UND läuft unabhängig von Testergebnissen.                     | Der `build`-Job nutzt kein `actions/checkout@v4` (Code fehlt) und besitzt keine Job-Abhängigkeit (`needs: test`).                                  | `actions/checkout@v4` im `build`-Job ergänzen und `needs: test` hinzufügen.                                                                                                                 |
| **8. Release-Fehler (Artifact):** `gh release create` findet `build/app.zip` nicht, da `release` auf einem neuen, leeren Runner läuft.                                | Im `release`-Job fehlte der Schritt zum Herunterladen des zuvor im `build`-Job hochgeladenen Artifacts.                                            | `actions/download-artifact@v4` (Download von `app-paket` nach `build/`) vor dem Schritt „Release erstellen“ ergänzen.                                                                       |
| **9. Release-Fehler (Repository):** `gh` kann das Ziel-Repository nicht ermitteln, da kein lokales Git-Repository (`.git`) auf dem Runner vorhanden ist.              | Im `release`-Job fehlte `actions/checkout@v4`; ohne Checkout hat der Runner keine Git-Metadaten, die `gh release create` zur Repo-Erkennung braucht. | `actions/checkout@v4` als ersten Step im `release`-Job ergänzen.                                                                                                                             |
| **10. Sicherheitsrisiko & Falsche Deploy-Auslösung:** Secret-Wert wird im Klartext im Log angezeigt und Deployments starten bei jedem Pull Request auf allen Branches. | Secret wird direkt per `echo` ausgegeben. Zudem fehlen Bedingungen (`if: github.ref == 'refs/heads/main'`), `environment: production` und `needs`. | `needs: [test, build]` setzen, `if: github.ref == 'refs/heads/main'`, `environment: production` und Secret nur als Env-Variable nutzen ohne den Wert auszugeben (z. B. `${#DEPLOY_TOKEN}`). |
